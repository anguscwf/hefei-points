## 本次完成

1. 服务端新增设备专用 `GET /api/v2/me/reward-rules`。它只接受设备 Access Bearer，并在读取前复验 active session、binding、当前监护授权、儿童处理状态和 `POINT_REQUESTS_ENABLED`。
2. 接口只返回当前家庭可申报 reward 规则的最小规范化字段，过滤 `max=0` 项，不返回 punish/special、提示、别名、家庭、儿童、设备、内部数据库 ID 或其他共享配置。
3. 规则分页使用独立用途派生的 AES-256-GCM 不透明游标，AAD 绑定家庭、儿童和设备，载荷绑定规则 revision、快照指纹和索引。跨家庭、跨儿童、同一儿童的第二台设备、篡改和规则变更均稳定拒绝；规则变更返回 `REWARD_RULES_CHANGED`。
4. 规则列表和积分申请创建共用同一当前规范化快照，避免列表展示值与提交校验分叉。缺失、畸形或没有可申报项的当前规则 fail closed，不回退到默认家庭或旧共享配置。
5. HarmonyOS transport 增加且只增加设备 reward rules、积分申请创建和本人申请列表的固定方法/路径/凭据/body allowlist；成人 `GET /api/v2/point-requests` 仍被禁止。
6. 客户端 DTO 使用严格字段集、类型、范围、游标、重复 ID、分页上限和审批流水关联校验。创建 body 固定为 `clientRequestId`、`ruleId`、`points`、`description` 四个字段，不允许客户端提交家庭、儿童、设备、分类、流水来源或发生时间。
7. UI 新增当前规则选择、积分输入、不超过 120 字的单行说明、提交按钮、“我的申请”状态卡片和分页加载。规则、申请和草稿只在当前前台会话内存中存在，后台、换会话、撤权和隐私阻断会清除。
8. 新建独立 PointRequest AssetStore 意图仓，固定 alias，最大 1024 UTF-8 字节，使用 `DEVICE_UNLOCKED`、`REQUIRE_PASSWORD_SET=true`、`AUTH_TYPE=NONE`、`SYNC_TYPE=NEVER`、`IS_PERSISTENT=false` 和冲突即失败；写后读回并逐字节核验。
9. 创建申请必须先持久化规范化请求体、原幂等键和设备 binding，再允许发送。结果未知、429、畸形 mutation 响应或重启时，先在本人最近 50 条申请中按 `clientRequestId`、规则、积分和说明完整对账；未找到才用原 body 和原键精确重放。
10. 幂等冲突、结果不可用、本地清理失败或无法证明结果时保留并锁定原意图，不生成第二个键。只有申请创建 POST 的确定性 stale replay 才能清理该意图；Refresh 的同名错误不会误清积分意图。
11. 授权撤回或设备/会话撤销在服务端立即使请求和凭据失效；客户端下一次收到确定性 `SESSION_REVOKED` / `CONSENT_REQUIRED` 时先清积分意图、再清会话。若意图清理失败，客户端保留会话但锁定业务，避免留下无法恢复的孤立文字。`CHILD_PROCESSING_BLOCKED`、`CHILD_DATA_INCOMPLETE` 和功能门关闭只清内存业务视图，并保留会话及原未决意图等待安全恢复。
12. 并发和生命周期覆盖重复点击、响应丢失、跨重启恢复、Refresh-before-replay、后台晚到响应、规则变更重启分页、绑定不匹配、撤权清理顺序和本地 Vault 故障。

## 明确未实现的边界

- 申请补充、取消和重新提交仍未进入 HarmonyOS 客户端。当前设备契约没有单条详情和写操作结果对账，网络结果未知后不能可靠证明操作结果；不得复用成人接口或靠本地猜测补齐。
- 未决积分申请意图没有自动过期。长期开关关闭、幂等冲突或对账不可用时，儿童文字可能持续保存在本机 AssetStore；生产前必须批准逐类保留期限和监护人授权的安全放弃/清除流程。
- 启动恢复只先扫描本人最近 50 条申请。更早结果依靠原幂等键精确 POST 及服务端 stale/result 语义收敛，不代表客户端已提供任意历史深度的本地搜索。
- 服务端撤权即时阻断并撤销设备会话；客户端没有 Push 撤权通知，只会在下一次确定性请求响应或恢复时清理本地状态。
- “我的申请”当前使用内存分页追加；长历史性能、空态/可访问性和儿童友好视觉仍需真机与产品验收。
