## 本轮实现

### 1. 完整刷新与分页使用同一严格快照契约

`ChildSessionCoordinator` 对首次加载、完整刷新和加载更多统一验证每个响应页：

- 按服务端契约精确保持 `(submittedAt, id) DESC` 严格降序；
- 申请 ID 必须是 canonical `point_request_<32 位小写十六进制>`，并在本页和已接受历史页之间唯一；
- 来源设备可见的 `clientRequestId` 只能映射到同一申请，本页、跨页都不得复用；
- 完整刷新不得把旧快照中已见的可见 `clientRequestId` 改绑到新 ID；
- 对完整刷新中仍可见的旧项逐项检查申请/规则快照身份、revision、状态、正文、处理字段和真实时间单调性；缺席只表示当前页不可见，不推断删除或终态。

低 revision、同 revision 内容漂移、真实时间回退、终态后演进、不可变身份替换、重复或乱序项都在应用前稳定返回 `PROTOCOL_ERROR`。比较 `requestInfo` / `decision` 时按字段语义比较，不依赖 JSON 对象键枚举顺序；非空 `requestInfo` 的键顺序变化有直接正向回归。

### 2. 游标历史阻断停滞与循环

继续分页必须携带精确当前游标。协调器在接受页面前检查：

- 空页不能携带非空下一游标；
- 下一游标不能等于请求游标；
- 下一游标不能命中已接受的游标历史，因而自环和 A→B→A 等多页循环都会在应用前失败；
- 新页不能与旧页产生申请 ID 或可见 `clientRequestId` 冲突，也不能破坏跨页严格排序。

Access 过期仍只允许既有 proof/Refresh 流程安全轮换一次，再以精确原游标重试；不会生成第二个业务意图或替换申请幂等键。

### 3. 协议污染后的原子冻结

列表读取发生确定性协议错误时，协调器保留此前已经验证的申请列表和 selected detail，避免用未验证页面覆盖可信快照；详情读取在发请求前即清除 selected detail，因此详情 `PROTOCOL_ERROR` 只保留已验证列表，不恢复旧 selected detail。两类协议错误都会原子清空 reward rules、规则/申请游标及游标历史，禁止继续分页和沿用旧规则创建新申请。

存在未决申请创建 intent 时，加载更多在协调器和 `Index` UI 双层禁用，不能绕过 S8 的恢复顺序。`FEATURE_DISABLED` 或 `CHILD_PROCESSING_BLOCKED` 继续清除业务视图；它们以及协议冻结都不写 PointRequestVault。

### 4. generation、迟到错误与撤权优先级

页面退到后台或本地 generation 变化后，普通迟到成功和普通迟到错误都不能覆盖新状态。确定性的 `SESSION_REVOKED` / `CONSENT_REQUIRED` 不因 generation 过期而被吞掉，仍执行既有“先清未决申请意图，再清设备会话”的撤权路径。客户端没有主动撤权推送；远端线性化完成后才发生的撤权，仍由下一次请求或生命周期切换触发本地清理。

### 5. 明确未扩张的边界

本轮没有：

- server route/service/repository、数据库 migration 或 production state；
- 新增或消费 operation reconcile、resubmit/cancel/PATCH 或其他申请 mutation；
- 持久 mutation intent/coordinator、AssetStore/Preferences/文件/剪贴板新槽位；
- retention 期限选择、guardian-authorized safe abandonment 状态机或新 ADR；
- 外部网络、真实 S19 authority/coordinator/deployer、部署、真机、签名、AppGallery 或儿童设备操作。
