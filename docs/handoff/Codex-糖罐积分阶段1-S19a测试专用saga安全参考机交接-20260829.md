## 本轮实现

### 1. 纯函数 test-only reference model

新增：

```text
server/test-support/synthetic-external-saga-reference-model.js
```

唯一入口：

```text
inspectSyntheticExternalSagaReferenceTraceForTest(document)
```

它只接受：

- 与 S19-readiness test seam 固定输出完全一致、`testOnlyOverridesUsed=true` 的 blocked report shape；
- 摘要化 test operation，包含 operation ID、artifact、configuration、secret version、target、变更前/期望目标状态、正整数 fence 和绑定完整输入的 fingerprint；
- coordinator、deployer、target、platform event source、state observer、health observer、no-effect proof issuer 七个 test participant；
- actor ID 与 fault-domain 两组各自两两分离的 exact-key synthetic trace。

production blocked report 即使其他字段相同，只要 `testOnlyOverridesUsed=false` 就稳定拒绝。纯函数只绑定 caller report 的形状和摘要，不能认证该对象确实由某次函数调用生成；输出固定 `callerProvidedReportOriginAuthenticated=false`。

### 2. 负向 saga 不变量

reference model 固定以下 test-only 约束：

- reservation 与 outbox 只能由一条 `test_only_reservation_outbox_atomic_commit` 事件同时表示；拆分事件不是可接受状态；
- accepted、queued、HTTP 2xx、outbox dispatched、delivery ACK 和 signed ACK 只能在原子参考事件之后计数，绝不推进；
- target admission、平台变更事件、独立 read-after-write 和 health 必须来自不同 participant/fault-domain，并绑定同一 operation/fingerprint/fence；
- 同 sequence 的完整 canonical event 精确相同才是 replay no-op；冲突 replay、gap、重复 event ID、跨 actor/fault-domain 或 binding 漂移稳定拒绝；
- 正向观察缺一时只返回 `reference_trace_incomplete_no_positive_conclusion`；只有完整 test shape 最多返回 `no_modeled_safety_violation_detected`；
- 任一返回都不能写成真实 `conformant`、`success`、`deployed`、`approved` 或 `authorized` 状态。

这些只检查 caller 提交的单条完整 trace。reference model 没有跨调用状态、状态 token、历史 journal 或防回滚锚，不能证明跨 trace 幂等、全局 operation/fence 高水位、线性一致 reservation 或历史连续性。

### 3. sticky UNKNOWN、矛盾证据与 no-effect

dispatch result UNKNOWN 进入独立 `test_only_dispatch_unknown_sticky`。在同一 trace 内，只允许：

1. 同 operation/fingerprint/fence 的 admission → platform event → independent read → health 完整 test shape；或
2. 在从未观察 admission/platform/read 的前提下，形成同时绑定变更前状态、target fence high-water、低 fence 拒绝声明和 `not_applied` 的 modeled no-effect shape。

矛盾 read 进入 `test_only_contradictory_observation_sticky`。它不能再由 no-effect 或第二次 admission 洗成完整 shape，稳定返回 `SYNTHETIC_S19A_TEST_SAGA_MODEL_CONTRADICTORY_EVIDENCE_UNRESOLVED` 或 `...UNKNOWN_STICKY`。

即使 test trace 形成 no-effect shape，输出仍固定：

```text
authoritativeNoEffectProofVerified=false
realExternalUnknownReconciledByThisModel=false
targetFenceEnforcementVerified=false
```

因此该 shape 不是权威 negative proof，也不允许释放真实 reservation 或复用 grant。

### 4. 补偿边界

S19a v1 不实现正向 compensation/rollback 链。独立健康观察为 unhealthy 时只进入：

```text
test_only_compensation_protocol_required
```

任何 compensation、rollback、release、refund 或 grant-reuse 事件稳定返回 `SYNTHETIC_S19A_TEST_SAGA_MODEL_COMPENSATION_PROTOCOL_UNAVAILABLE`。输出始终：

```text
compensationProtocolAvailable=false
compensationAuthorized=false
compensationPerformed=false
rollbackSafetyVerified=false
originalGrantReusable=false
```

### 5. 零副作用与生产图隔离

reference model 只依赖确定性的 `node:crypto` 和用于拒绝 Proxy 的 `node:util.types`。它不读取环境或当前时间，不访问文件、SQLite、网络、stdin/stdout，不启动子进程、worker 或 timer，也不调用 S17～S19 production API。

本轮没有：

- `scripts/` CLI 或 package script；
- production server import/export；
- 临时 SQLite、journal、sidecar 或持久 receipt；
- migration 011、新业务表或 readiness 状态；
- endpoint、SDK、凭据、trust root、外部协议 adapter、真实 reservation/outbox/fence/admission/观察/补偿/部署器。

committed synthetic production provenance 因此仍精确锁定 43 个实现文件和 001～010 十项迁移。

## 安全复核修正

三路只读复核发现并关闭了以下 P1：

1. admission/platform 后的矛盾 read 曾能落入通用 UNKNOWN，再被 no-effect shape 洗成“完整”；现已把 dispatch UNKNOWN 与 contradiction UNKNOWN 分态，并用资格位和已有证据双重阻断。
2. non-enumerable 必需字段曾可能被 canonical hash 忽略，从而绕过冲突 replay；现要求全部对象/数组为 exact own enumerable data descriptors，拒绝 symbol、accessor、稀疏或隐藏字段。
3. 容器 Proxy、超限 dense trace 和应为 scalar 的 Proxy/cycle/BigInt 曾可能在稳定拒绝前触发 trap、递归或资源消耗；现使用 `node:util.types.isProxy` 前置拒绝，先检查 128 事件上限，并在任何 hash 前精确约束 operation action 与全部 event scalar。

回归覆盖 scalar/container Proxy 零 trap、自引用 action、BigInt payload、non-enumerable report/replay、矛盾证据后 no-effect/second admission，以及 target pre-state 绑定。最终独立安全复核未发现剩余 P0/P1。
