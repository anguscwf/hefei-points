3. transport 只允许六类具体调用：claim-by-code、claim complete、设备 Refresh challenge、Refresh 轮换、本人摘要和本人流水。流水 query 只允许 `limit=1..50` 及 69 字节游标的 92 字符 canonical base64url 表示；请求不提供家庭、儿童、设备或会话身份选择。
4. 设备身份使用 HUKS P-256 / SHA-256，`KEY_OVERRIDE=false`，并显式使用仅解锁态可访问的 ECE 存储级别。公钥导出前核验 91 字节 canonical P-256 SPKI；签名接受 raw P-256 或严格 DER 并规范化，拒绝零值和非 canonical DER。
5. 配对 proof 严格核对无 CR、无尾换行的六行 `tangguan-device-proof-v1` signing payload、purpose、challenge、binding 和 session 上下文。监护确认只推进服务端状态，孩子端 proof 完成后才取得首代 Access/Refresh。
6. 会话 envelope 使用 AssetStore `DEVICE_UNLOCKED`、`REQUIRE_PASSWORD_SET=true`、`SYNC_TYPE=NEVER`、`IS_PERSISTENT=false` 和固定 alias。更新不做 remove/add，按 revision 串行化、写后读回并逐字节复核；备份恢复关闭，备份 Extension 已移除。
7. 本地状态按 UNPAIRED、CLAIM_INTENT、WAITING_GUARDIAN、COMPLETE_RESULT_UNKNOWN、ACTIVE、REFRESH_ISSUE_INTENT、REFRESH_COMPLETE_INTENT 相位互斥。无关相位夹带 Token、签名、短码或幂等字段会按 `LOCAL_STATE_CORRUPT` fail closed。
8. 写请求在发送前持久化完整恢复意图。结果未知时只重放原短码/claim、旧 Refresh、challenge、签名和幂等键，不按客户端 proof 过期时间提前丢弃服务端已提交结果。只有服务端明确返回 `CHALLENGE_EXPIRED`，才为尚未轮换的 Refresh 持久化新 issue 键。
9. `PAIRING_CODE_INVALID` 等确定性配对失败清回 UNPAIRED 并保留本机密钥/公开 ID；服务端持久失败计数与锁定仍是猜码防护权威。撤回或撤销会在服务端立即使凭据失效；客户端下一次请求收到确定性 `SESSION_REVOKED` / `CONSENT_REQUIRED` 后，清除本地 Token 与业务内存视图并要求重新配对。
10. Access 临近过期时用旧 Refresh 请求单个 challenge，以 HUKS 签名后轮换；新会话必须更换 session ID、Access、Refresh，rotation 必须加一，Refresh 截止保持固定。畸形 mutation 2xx 按结果未知保留意图，只读畸形 2xx 为确定协议错误。
11. UI 覆盖 6 位短码、等待监护确认、原样恢复、会话恢复、本人余额和分页流水。儿童数据只在内存展示，页面进入后台即清除；不记录动态日志，不写 Preferences、普通文件、剪贴板或硬件设备标识。
