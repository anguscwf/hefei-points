## 本次完成

1. 新增显式 deployment profile。`DEPLOYMENT_TIER=synthetic` 只允许与 `NODE_ENV=production` 同时使用，以测试生产代码路径但保持资源身份隔离；非 production 环境只能是 local，production profile 又会拒绝任何 synthetic 标记混入。
2. synthetic 运行要求三项精确确认、非生产 canonical HTTPS API origin、同源法律证据、与生产不同且格式固定的微信 AppID、显式 AppSecret、受约束合成数据集 ID和非 debug 日志级别。规范化运行契约只返回“secret 已存在”，不返回秘密值。
3. 四个 synthetic 核心门 `HARMONY_CHILD_ENABLED`、`CHILD_ENROLLMENT_ENABLED`、`DEVICE_PAIRING_ENABLED`、`POINT_REQUESTS_ENABLED` 必须逐字为 `true`；`CHILD_DATA_RIGHTS_ENABLED` 和两项 `LEGACY_*` 必须逐字为 `false`。production profile 反向要求全部儿童门逐字为 `false`、法律发布配置为空，防止 synthetic 配置误入生产。

## 审计透明说明

- preflight 的“实现与 HEAD 一致”允许唯一的工作树差异是 LF 与 CRLF 规范化；孤立 CR、其他字节变化、index/tree/commit/OID 或 batch 变化都 fail closed。它不声称工作树其他非实现文件干净。
- verifier 与 guard 信任当前本机 Node/Git 二进制和同权限操作系统环境；绝对 Git 路径、前后 executable identity 和最小环境降低 PATH/config 替换风险，但不是 OS 级沙箱，也不能抵御已取得相同 OS 权限的进程级攻击。
- 本轮 verifier 在 Node `v24.15.0` 运行；preload 守卫要求 `Module.registerHooks`，对缺失该 API 的旧 Node 会 fail closed。受控 synthetic 部署前仍须把批准的 Node 运行线与当前 `engines >=22.5.0` 声明对齐并在该精确运行线重跑预检。
- verifier 在创建临时根后、进入主要清理块前仍存在只可能遗留空验证目录的极小运行时失败窗口；不会递归误删仓库或发布含秘密证据。测试和本轮诊断结束时归属本预检的临时根残留为 0。
- 早期对抗诊断曾留下 4 个本工具自有临时验证根；已逐一核对物理路径、固定前缀和内容后在同一 PowerShell 边界内安全删除，未触碰其他临时目录。
