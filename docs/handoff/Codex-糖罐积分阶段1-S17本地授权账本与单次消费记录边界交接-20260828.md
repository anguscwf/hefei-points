## 本轮实现

### 1. S16 schema 2 与独立 checkpoint 生产 API

S16 成功输出从 schema 1 扩展为 schema 2，新增并严格验证 S17 所需的安全绑定：

- `trustPolicyIdSha256`、policy 内容摘要和 revision；
- `consumerIdSha256` 与 `targetEnvironmentSha256`；
- checkpoint sequence/envelope 摘要；
- subject、candidate、source commit、实现树与配置摘要；
- approval envelope、grant ID 和 grant envelope 摘要。

支持层新增 `verifySyntheticRevocationCheckpoint` 生产 API。它沿用环境摘要钉住的独立 Ed25519 策略、路径安全和前后二读，只验证一个签名 checkpoint 并返回冻结 schema 1 摘要。生产 API 与 test-only seam 的 provenance 不能混用；API 仍不认证策略权威、revocation authority 真实身份，不信任本机时间，也不证明 checkpoint 为权威最新。

S16 CLI 自身仍然只读、无消费账本，结果继续是 `signed-bundle-valid-against-provided-policy-unconsumed`。

### 2. 独立 ledger identity 与 genesis

新增：

```text
npm run init:synthetic-authorization-ledger
```

命令要求非 TTY、最多 768 KiB、单行 canonical JSON，以及：

```text
SYNTHETIC_AUTHORIZATION_LEDGER_INIT_ACK=initialize-local-ledger-not-authority-v1
```

固定文件 `synthetic-authorization-ledger.sqlite` 必须位于仓库、synthetic 数据根和信任策略目录之外的批准直接父目录，与仓库处于同一本地卷，最大 16 MiB。UNC/device、异卷、dot-segment、混合分隔符、任一祖先 symlink/junction、非普通文件、多链接和路径/身份漂移均 fail closed。

genesis 在一个 `BEGIN IMMEDIATE` 内固化 ledger/consumer/target、policy、签名 checkpoint、文件 device/inode、批准父目录和主机/OS 账号上下文。checkpoint 在事务开始后和提交前各验证一次；任何漂移、完成时过期或本机观察时间倒退都会拒绝。精确原请求可重放，不同请求或输入不得接管既有 ledger。

ledger schema 1 是仓库外独立 SQLite 格式，不是服务端业务迁移 `011`；当前迁移仍精确为 001～010。

### 3. 本 ledger checkpoint 单调与累计吊销

ledger 对已观察 checkpoint 执行：

- 低 sequence 拒绝 rollback；
- 高 sequence 只允许精确 `+1`，跳号拒绝；
- 同 sequence 必须是同摘要；不同摘要视为 fork；
- policy ID、内容摘要与 revision 必须保持 identity 绑定；
- revoked key、principal、approval 和 grant 四类集合只能累计。

同序列 fork 或下一 checkpoint 删除任一已观察吊销项，会提交不可变 block 并永久封锁该 ledger。rollback/gap 不推进。有效新 checkpoint 即使随后 bundle、绑定、唯一性或有效期失败，也会与稳定 rejection 一起提交，防止调用方换请求降级回旧 checkpoint。

这只证明本 ledger 实例对自己已观察历史执行了约束，不证明全局最新 checkpoint 或跨主机一致性。

### 4. 本地 compare-and-record、幂等与唯一性

新增：

```text
npm run consume:synthetic-deployment-grant
```

命令要求：

```text
SYNTHETIC_AUTHORIZATION_CONSUME_ACK=record-local-single-use-not-deployment-v1
```

输入只包含 schema 1 固定 purpose、唯一 request ID 和完整 S16 verification 输入文档。消费在同一个 `BEGIN IMMEDIATE` 中：

1. 全量检查 schema、trigger、外键、checkpoint/receipt/rejection/block 摘要和 ledger context；
2. 在 verifier 前恢复精确历史 request；
3. 验证 checkpoint、重跑 S16 verifier 并要求 schema 2 结果，再在提交边界验证 checkpoint；
4. 检查 policy/consumer/target、grant、grant envelope、approval envelope 和 target/source/implementation/configuration 绑定；
5. 原子写入不可变 receipt，或对授权束终态失败/唯一性冲突写入不可变 rejection。

同 request、同完整指纹可恢复历史 receipt/rejection；同 request 不同指纹稳定冲突。同 grant、grant envelope、approval envelope 或候选目标元组的新 request 不会产生第二条 receipt。

历史 receipt replay 在 verifier 前恢复，不伪称当前 ledger head、外部 approval 或 checkpoint 已于本次重验。提交结果不能证明时返回 `SYNTHETIC_AUTHORIZATION_LEDGER_RESULT_UNKNOWN`，只允许用精确原请求恢复，禁止换键试探。

### 5. SQLite 并发、崩溃恢复与篡改边界

账本固定使用 `journal_mode=DELETE`、`synchronous=FULL`、15 秒 busy timeout 和 `BEGIN IMMEDIATE`。WAL/SHM 始终不属于该 profile 并被拒绝；DELETE journal 可能是合法同行事务的瞬态文件或崩溃遗留 hot journal，既有 ledger 会让 SQLite 在可写排他入口内先恢复，再完成全量验证。不会在锁前把正常同行事务误判为攻击，也不会自行删除未知 sidecar。

所有 identity、checkpoint、receipt、rejection 和 block 都由精确 schema、不可变 trigger 和摘要复核保护；修改/删除记录、缺失 trigger、换文件/context、超限或完整性失败都会 fail closed。两个真实 Node 进程争抢同一 grant 时仅一个本地 receipt，另一个稳定拒绝；同 request 并发形成一次提交和一次 replay。

### 6. CLI、脱敏与始终未授权

- 两个 CLI 除 `--help` 外不接受参数；stdin 拒绝 CRLF、非 canonical JSON、敏感环境明文和超过 768 KiB 输入。
- 成功 stdout 是一行脱敏 JSON，不回显路径、策略正文、公钥、签名、原始 request/grant/approval ID、origin、AppID、AppSecret、dataset 或数据库内容。
- 失败 stdout 为空，stderr 只输出一行稳定错误码。
- 写入只发生在独立 ledger；synthetic 业务 SQLite、生产数据、网络、部署器和 production 儿童门均不触碰。

初始化成功、首次消费成功和历史 receipt replay 的 JSON 输出全部固定为：

```text
deploymentAuthorization=not_granted
productionChildGateState=not_observed
childUseAuthorization=not_granted
operations.deploymentPerformed=false
```

首次消费成功的 `deploymentGrantStatus=local_single_use_record_committed` 与历史 receipt replay 的 `historical_local_single_use_record_replayed` 都只描述本 ledger 本地记录，不是实际部署或全局消费证明。历史 rejection replay 仍是失败路径：stdout 为空，只恢复原稳定错误码。

## 安全与并发回归

新增或加强的测试覆盖：

- genesis 双 verifier、精确 replay、提交前故障回滚和提交后结果未知恢复；
- production/test-only provenance 隔离，防止 test receipt 被复制“洗”为生产结果；
- checkpoint rollback、gap、精确 `+1`、同序 fork、四类累计吊销和永久 block；
- 有效 checkpoint 推进与 bundle 终态 rejection 同事务记录；
- policy、consumer、target、grant、approval、candidate/source/config 作用域隔离；
- 本机时间回滚、checkpoint/bundle 最早有效期和提交边界过期；
- receipt/rejection/block/schema/trigger 篡改与文件/context 跨路径复制；
- 相同 request 精确 replay、不同指纹冲突、grant/approval/target 唯一约束；
- WAL/SHM 拒绝和真实 hot DELETE journal 崩溃恢复；
- 两个真实 Node 进程的同 grant 与同 request 确定性竞争；
- 两个 CLI 的 help、ACK、canonical stdin、敏感输入和稳定脱敏错误。

所有测试只使用合成家庭、合成配置、内存 Ed25519 密钥、系统临时目录与临时 SQLite，没有接触生产资源。
