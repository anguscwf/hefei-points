## 本次实现

1. 新增 `npm run bootstrap:synthetic-database`。CLI 除 `--help` 外不接受参数，只从非 TTY stdin 读取最多 16 KiB 的单行 canonical JSON；密码不得进入 argv、环境变量、普通文件、日志、证据或仓库。
2. 输入精确限定一个 `synthetic_admin_` 成人管理员、合成批准引用、与环境一致的数据集标识，以及四类各一次的获批 synthetic 法律元数据。工具不接受真实身份、正式法律正文、生产资源或儿童业务数据。
3. 目标 SQLite 路径必须此前不存在。主文件以 `wx`、私有模式和单链接约束排他创建；打开前后以真实路径、文件类型、链接数及 `dev + ino` 复核身份。已迁移空库、删空旧库、未知 schema、残留 `.secret`、WAL/SHM 或业务数据一律拒绝接管。
4. 新增迁移 `010_synthetic_bootstrap_receipt.sql`。001～010 迁移、默认家庭收敛、一个 scrypt 管理员、四类法律元数据和单例完成回执在同一 `BEGIN IMMEDIATE` 中提交；回执不可二次插入、`INSERT OR REPLACE`、更新或删除。
5. 迁移执行集合固定为显式 001～010 清单，目录中额外、缺失、链接或非普通 SQL 返回 `MIGRATION_SET_INVALID`；已应用账本必须是该清单的有序前缀，否则返回 `MIGRATION_LEDGER_INVALID`。生产迁移备份门与迁移事务都会先复核账本。
6. 回执绑定 deployment、S13 marker、schema、dataset、批准引用、管理员及监护关系声明。synthetic runtime 在任何可写 SQLite 打开、迁移或 Token secret 创建前，先只读验证回执及当前环境，再以同一文件身份可写 reopen；最终验证后再次复核身份。缺失回执返回 `SYNTHETIC_BOOTSTRAP_REQUIRED`，跨环境数据库返回 `SYNTHETIC_BOOTSTRAP_CONTEXT_MISMATCH`。
7. 提交前故障确认完整回滚后，只删除仍能证明属于本次创建的同 inode 空文件；无法证明回滚或清理结果时返回 `BOOTSTRAP_RESULT_UNKNOWN`，禁止自动猜测。提交后结果未知只允许完全相同请求在运行状态演进前恢复为 `replayed`。
8. 同请求并发形成一个 `created` 与其余安全 `replayed`；不同请求并发只允许一个提交，其余稳定 `BOOTSTRAP_CONFLICT`。完成后的管理员可走普通运行路径轮换密码或绑定 OpenID，但 bootstrap 不再充当状态查询、轮换或法律更新接口。

## 安全与并发边界

- runtime 与 bootstrap 对当前可观察到的路径替换、链接、文件身份、迁移集合、账本和环境漂移均 fail closed。同权限写入者在两个检查点之间“替换后恢复”的不可观察瞬态仍必须由专用 OS 账号、ACL、所有权和主机隔离外部硬门消除。
- `.synthetic-bootstrap.lock` 只在 stdin 完整关闭后获取，避免未闭合秘密输入长期占锁；锁释放不能证明文件身份时返回结果未知，不自动夺锁或删除他人文件。
- 一旦出现未知 SQLite/WAL/SHM、无法证明事务结果、身份漂移或清理失败，必须隔离整个候选根并按手册人工处置；不得删表、清行、手改迁移账本/回执或复制数据库继续。
- 成功证据只包含摘要、计数、布尔边界和稳定状态，不包含密码、管理员 ID 明文、origin、AppID、AppSecret、本机路径或法律正文。`externalHardGates=false` 只表示本命令没有完成外部核验。
