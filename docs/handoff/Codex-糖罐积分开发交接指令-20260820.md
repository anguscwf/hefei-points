## 5. HarmonyOS 孩子端 MVP 目标（核心任务）

### 5.1 决策背景（2026-08-19 华为工单 D635177 确认）

- AppTest / 邀请测试**不支持实名未成年人账号**；儿童设备保持未成年人模式 + 远程守护下，当前无官方测试分发渠道。
- 结论：**双轨分发** —— 成人预发布验证轨（邀请测试/模拟器/自动化/Mate 80 真机）+ 儿童正式使用轨（AppGallery 正式审核后安装）。

### 5.2 MVP 目标（薄 MVP，版本线见方案 8.1）

> 首发为 `0.2.0 (20000)`，只含「监护人授权与配对 → 查看积分 → 申报任务 → 家长审批 → 查看结果 → 解绑/删除」薄闭环。照片、Push、用机兑换、第三方统计默认关闭。

**孩子端能力**：查积分（总/冻结/可用）、今日任务与可申报事项、文字申报、查审批状态、安全配对（不共享家长密码）。

**家长端能力**：家庭待办箱、单条审批/调分/退回/驳回、批量通过、认领用机兑换、监护人授权与儿童数据行权入口。

**后端能力**：`guardian_consents` / `device_bindings` / `point_requests` / `time_redemptions` / `notification_outbox` 数据对象；申请状态机；冻结积分；审计日志；revision 并发保护；幂等。

### 5.3 关键规则（MVP 方案 5.4 摘要）

- 同一孩子同一时刻只允许一个有效用机兑换申请。
- 暑假模式手机+平板合计每天 120 分钟（2026-08-31 结束）；**上学模式未配置前 `time_redemptions_enabled` 必须保持 false**。
- 允许时段 11:00~14:00、21:00~23:00；套餐不跨时段。
- 先冻结后执行；发放成功才扣分；失败释放冻结；不确定进待核对。
- 不在华为侧自动读写系统奖励积分；`MANAGE_SCREEN_TIME_GUARD` ACL 不申请。

## 6. Git 项目管理规范（对齐 AnHub 模式）

> 参考 AnHub 交接文档 2026-08-19 与 NGL AGENTS.md 工作流规范。Codex 接手后应将此规范固化到 `hefei-points/AGENTS.md`。

### 6.1 仓库工作流

1. **master = 稳定主线**：master 只能包含已验证、可部署的代码。
2. **短期分支**：每个需求一个分支，命名 `feat/hefei-YYYYMMDD-主题`；完成并验证后合入 master，合入后删分支。
3. **精确暂存**：`git add <具体文件>`，禁止 `git add .`。
4. **提交信息规范**：`feat(miniapp): 描述` / `feat(server): 描述` / `feat(harmonyos): 描述` / `fix(...)` / `chore(...)` / `docs(...)`。
5. **先核对后动手**：每次开工先 `git status` + `git log --oneline -3`，确认基线。
6. **不静默覆盖**：工作树有未提交改动时，先确认归属再操作。
