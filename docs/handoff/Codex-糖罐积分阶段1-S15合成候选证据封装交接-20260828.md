## 本轮实现

### 1. S12/S14 来源与配置绑定

1. S12 实际候选 preflight 当前输出 schema 4，审计集合从 S14 的 31 个扩展为 34 个实现文件，迁移仍精确为 001～010。`verify:synthetic-api-preflight` 只做提交实现/offline guard 的内部 fixture 自检；实际 artifact 由同一配置的 `preflight:synthetic-api -- --output <全新临时绝对目录>` 生成。
2. 配置聚合绑定规范化 `TRUSTED_PROXIES` 实际集合与 AppSecret-keyed HMAC，只输出聚合摘要，不回显代理、secret、origin、AppID、dataset 或本机路径；它用于检测配置漂移，不证明 secret 独立或身份真实。
3. S14 canonical 输入新增 `candidateProvenance.sourceCommit`、`implementationTreeSha256`、`configurationSha256`；不可变回执原样固化三值。
4. 回执新增 `administrator_verifier_sha256`，S15 pristine 核验要求 live 管理员 verifier 与 bootstrap 时一致；正常 runtime 仍可轮换密码，但轮换后该根不再是 S15 候选。
5. 迁移 010 在尚无外部 S14 数据库或部署的前提下原地扩展。任何旧 S14 数据库均 fail closed，不升级、不补列、不接管，必须从当前候选的全新 S13 根重新 bootstrap。

### 2. Phase A：30 分钟 machine subject

新增 `npm run capture:synthetic-candidate-evidence`。它要求非 TTY、最多 256 KiB、只允许可选 LF 的单行 canonical JSON，以及：

```text
SYNTHETIC_CANDIDATE_EVIDENCE_ACK=assemble-review-only-not-deployment-v1
```

输入精确绑定同一候选的 S12 schema 4 artifact、S13 bootstrap 前空根 evidence、S14 bootstrap evidence 和非敏感 candidate ID。工具随后通过锁定绝对 Git 身份重新取得当前 committed provenance/S12 配置聚合，并另行核对双轮 S13 根快照、物理根/父目录/root/data/SQLite 文件身份、主机/OS 账号上下文和 live SQLite 状态。

SQLite 通过只读 immutable URI 打开；主文件在打开前后做完整字节摘要与元数据快照，并与一个内存参考 schema 比对。候选必须精确保持一个默认合成家庭、一个未轮换成人管理员、四类法律元数据、一个不可变回执、十项迁移、零儿童与业务状态，且没有 WAL/SHM/Token secret。输出只含摘要与布尔事实，TTL 固定 30 分钟。

边界始终明确：

- `historicalSequenceVerified=false`
- `runtimeSecretIndependenceVerified=false`
- `localClockExternallyTrusted=false`
- `externalFactsVerifiedByThisCommand=false`
- `deploymentAuthorization=not_granted`
- `productionChildGateState=not_observed`
- `childUseAuthorization=not_granted`

`subjectSha256`、`candidateBindingSha256` 和 root context 等外层摘要均未签名；S12 sensitive binding 内部虽含 AppSecret-keyed HMAC，也不是 subject 签名或外部批准。当前数据库观察不能证明历史顺序，同权限写入者在核验间修改后完整恢复的瞬态风险仍需外部 ACL/所有权和审计门约束。

### 3. Phase B：19 项未认证声明信封

新增 `npm run finalize:synthetic-candidate-evidence`。它接收原 Phase A 输入、原 machine subject 和固定顺序的 19 项声明；每项精确绑定 gate、subject、互不重复的非明文证据引用摘要、声明角色、来源类型、观察/到期时间，并且只能声明：

```text
state=declared_satisfied_not_authenticated
signatureStatus=not_verified
```

门项覆盖 AppID provisioning、开发者授权、AppSecret 独立性、request/business domain、DNS、TLS、代理/端口、OS 账号、ACL、所有权、磁盘、备份、数据库、运行 secret、基础设施连通、法律发布、DevTools 域名/TLS 校验和生产根隔离。

Phase B 会在 finalize 时完整重跑 Phase A 状态核验，拒绝 HEAD/config/root/数据库漂移、过期 subject、跨 subject、缺失、增加、乱序、伪称验签或时间无效的信封。`observedAt` 必须位于 capture 后且不晚于 subject 到期；final 输出有效期取 30 分钟 subject 与最早声明到期的较早者。

成功结果只表示 `attestation-envelopes-present`，并继续明确：

```text
attestationAuthenticityVerified=false
externalFactsVerified=false
externalFactsVerifiedByThisCommand=false
deploymentAuthorization=not_granted
productionChildGateState=not_observed
childUseAuthorization=not_granted
```

### 4. CLI、脱敏和 fail-closed

- 两阶段都不接受业务参数；`--help` 明示只读 Git、只读 SQLite、内存参考库以及不持久化、不联网、不部署、不验证外部事实、不授权使用。
- raw 与 JSON 转义形式的当前敏感配置都会在解析前拒绝；candidate ID 只输出摘要。
- 失败 stdout 为空，stderr 只输出单行稳定错误码，不回显路径、SQLite 异常、origin、AppID、AppSecret、dataset、管理员或证据正文。
- 只允许预检所需 `createHash`/`createHmac` 纯计算；离线守卫继续阻断随机数、网络、SQLite、非 Git 子进程、worker、动态模块入口和边界外文件操作。
- 命令只输出 stdout，不自行保存证据；持久化必须由获批外部证据消费者完成。
