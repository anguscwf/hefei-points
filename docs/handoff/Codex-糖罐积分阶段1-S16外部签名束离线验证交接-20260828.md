## 本轮实现

### 1. 独立公开信任策略

新增：

```text
npm run verify:synthetic-external-approval
```

命令要求非 TTY、最多 512 KiB、只允许可选一个 LF 且拒绝 CRLF 的单行 canonical JSON，以及显式确认：

```text
SYNTHETIC_EXTERNAL_APPROVAL_ACK=verify-signatures-only-not-deployment-v1
```

输入不能携带公钥或信任策略正文。公开策略只能通过以下环境值指定：

```text
SYNTHETIC_APPROVAL_TRUST_POLICY_FILE
SYNTHETIC_APPROVAL_TRUST_POLICY_APPROVED_PARENT
SYNTHETIC_APPROVAL_TRUST_POLICY_SHA256
```

策略文件必须是 approved parent 的 canonical 直接子文件，位于 canonical 仓库和 synthetic 数据根之外，并与 canonical 仓库处于同一本地卷。UNC、device path、异卷、dot-segment、混合分隔符、任一祖先 symlink/junction、非普通文件、多链接文件、超过 128 KiB、POSIX group/world-writable，以及验证前后身份、内容或摘要漂移均 fail closed。

这个文件位置和调用方提供的 SHA-256 仍不证明策略来自权威发布者。策略置入、ACL、所有权、轮换和审计属于 S17 外部硬门。

### 2. Ed25519 签名、角色与职责隔离

公开 key 采用固定 Ed25519 SPKI DER 形状；`keyId` 等于 canonical 44-byte SPKI DER 的 SHA-256。base64url 必须严格规范，签名使用四个互不替代的 domain-separated payload：

- gate verification；
- revocation checkpoint；
- independent approval；
- deployment grant。

策略角色固定为：

- `external_gate_verifier`
- `deployment_approver`
- `deployment_grant_issuer`
- `revocation_authority`

19 项 gate 必须与 S15 顺序、角色、来源类型、subject、目标环境、source commit、实现树、配置、root context、证据摘要和审计摘要精确绑定。approval 必须由独立 approver 签名；grant 必须由独立 issuer 在 approval 后签发，并绑定指定 consumer，最长 5 分钟，只允许一次 synthetic API 部署动作。declarant、verifier、approver、issuer 和 revocation authority 之间执行固定职责隔离。

### 3. 独立吊销 checkpoint 与时效

bundle 必须包含由 `revocation_authority` 独立签名的 checkpoint。它支持撤销 key、principal、approval 和 grant，并且：

- `issuedAt` 不得来自未来；
- 必须不早于全部 gate、approval 和 grant 的最晚签发时间；
- checkpoint、签名 key、全部实际使用 key、gate、approval、grant 与 S15 subject 都必须在验证结束时仍有效；
- 最终 `validUntil` 取全部依赖中最早的失效时刻。

S16 不持久保存 checkpoint sequence，因此不能证明当前 sequence 是权威最新值，也不能阻止调用者回放一个仍在时效内但较旧的已签 checkpoint。持久单调、防回滚和并发撤销属于 S17。

### 4. S15 双时刻重算与本机状态绑定

S16 不信任输入中单独提供的“已通过”标志。它使用原始 S15 capture/finalize 输入和输出：

1. 按 S15 原 `finalizedAt` 重建历史 finalize 结果；
2. 以当前本机时间再次运行完整 S15 核验；
3. 检查 S12/S13/S14、当前绝对 Git 身份、配置、物理根、live receipt 和 pristine SQLite 仍一致；
4. 在签名束处理结束后再次按全部依赖时效收口。

生产入口没有可注入时间、Git、数据库或文件系统替身。测试专用 seam 明确标记为 test-only，使用它的结果会保守地把当前机器/Git/数据库检查保持为未验证；真实成功 CLI 回归则确认这些检查为真。

### 5. 始终未授权的输出边界

签名束全部有效时，输出仍固定为：

```text
deploymentGrantStatus=signature_valid_against_provided_policy_unconsumed
deploymentAuthorization=not_granted
productionChildGateState=not_observed
childUseAuthorization=not_granted
```

并继续保留以下未验证事实：

```text
trustPolicyExternallyAuthorizedByThisCommand=false
externalIdentityProofRetrievedByThisCommand=false
externalEvidenceContentRetrievedByThisCommand=false
externalAuditRecordRetrievedByThisCommand=false
trustedTimeVerified=false
revocationCheckpointMonotonicityExternallyVerified=false
approvalNonRepudiationEstablished=false
authorizationConsumptionVerified=false
replayProtectionPersisted=false
externalFactsVerifiedByThisCommand=false
```

`unconsumed` 只表示本命令没有执行消费，绝不表示该 grant 在任何外部系统中尚未使用。命令不联网、不写数据库、不创建 sidecar、不保存 replay/sequence/消费状态、不部署，也不修改 production 儿童门。

### 6. CLI、脱敏与稳定错误

- 成功 stdout 是一行脱敏 JSON，不回显路径、策略正文、公钥、签名、原始 approval/grant ID、证据正文、origin、AppID、AppSecret、dataset 或数据库内容。
- 失败 stdout 为空，stderr 只输出一行稳定错误码。
- 错误域覆盖参数/ACK/stdin、敏感输入、S15 来源漂移或过期、策略路径/内容/摘要/时效、吊销、key/identity、gate、签名、职责隔离、approval、grant、目标绑定、生产资源拒绝和未分类 fail-closed。
- 预检审计集合由 34 个扩展为 36 个实现文件，迁移仍精确为 001～010。
