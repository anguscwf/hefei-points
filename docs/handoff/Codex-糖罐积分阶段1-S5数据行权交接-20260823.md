2. 唯一创建入口为 `POST /api/v2/children/:id/data-rights-requests`，首版支持 `access`、`export`、`correct`、`delete`、`terminate`；授权撤回继续走既有 `/consents/withdraw`，并在同一事务写入 009 请求和完整状态事件。
3. 每种动作使用独立 reauth purpose，断言只允许同家庭同成人在有效期内消费一次。请求绑定本人对精确儿童的最新历史监护证据；跨家庭、兄弟姐妹、同家庭无证据和其他监护人的请求均按资源不存在处理。
4. access/export/correct 仅受独立 `CHILD_DATA_RIGHTS_ENABLED` 门控制；withdraw/delete/terminate、既有请求列表/详情及已授权短时导出在门关闭时仍可用，避免止损门封死安全或法定入口。
5. 请求、审计、幂等、privacy revision 和业务副作用均在 `BEGIN IMMEDIATE` 内完成。相同幂等键与相同指纹稳定重放，冲突载荷拒绝；revision CAS、事件先写和数据库触发器共同防止并发覆盖、证据改写及越级状态迁移。
6. access/export 只在完成后的五分钟窗口内动态生成最小快照，正文不落库；非法时间、明显时钟回拨及过期授权均 fail-closed。导出排除密码、OpenID、设备密钥/公钥、challenge、Token/Session/幂等摘要、fingerprint、token family、rotation 和内部 actor。
7. correct 首版只更正儿童当前别名，通过 privacy revision、旧值条件更新和新旧值 SHA-256 摘要防竞争；历史授权、积分流水、审批快照、规则及别名快照均不改写。
8. delete/terminate 只会原子进入 `deletion_pending`、撤销目标儿童全部绑定/挑战/设备会话、推进 legacy Token floor，并生成不可变 `blocked_policy/policy_pending` 作业。009 不提供删除执行器，数据库禁止伪造 completed、deidentified 或 deleted。
9. 授权撤回继续全局阻断处理、撤销目标儿童设备会话并推进 legacy Token floor；若已处于 processing_blocked/deletion_pending，则保留更严格状态和首次阻断时间。撤回前 Token 在撤回后及重新同意恢复 active 后仍失效。

架构边界见 [ADR-0008](../adr/0008-child-data-rights-retention-boundary.md)，阶段状态见 [阶段 1 实施清单](../plans/阶段1-现有能力审计与首批实施清单-20260823.md)。

## 已知非阻断项

- 当前完整导出会在单次请求内物化全部符合范围的数据，且外围只有通用 IP 限流。生产前需要增加 actor/request 专用限流，并改为流式或异步的完整导出；不能以静默截断替代法定数据副本。
- 当前不可变审计覆盖行权授权与处理状态，但每次实际下载尚未生成独立的 disclosure receipt。生产闭环应记录不含正文的 request、交付时间和最小结果元数据。
- `LEGACY_CHILD_LOGIN_ENABLED` 仍是默认关闭的生产硬门。若未来人为开启，旧登录入口还需在签发 Token 前强制校验 privacy state 为 active，并在重新授权时推进 Token floor，防止阻断期间新签发凭据在以后恢复可用。

## 仍未满足的生产硬门

- 正式隐私政策、儿童个人信息保护规则、儿童用户协议、敏感信息告知、显著易懂摘要、公开 URL 与真实行权联系方式尚未定稿发布。
- PIPIA、存量儿童数据盘点与整改、独立监护关系持续有效性方案尚未完成。
- 逐类留存/删除表尚未获批，仍需覆盖档案、授权、设备、会话、申请、流水、行权、审计、安全日志和备份，并明确期限、依据、责任人、争议处理和备份同步清理。
- 不可变账本的去标识、按儿童加密与密钥销毁方案尚未决策；009 的删除执行器必须保持不存在。
- 处理者清单与合同、生产密钥托管和轮换、迁移备份恢复演练、容量/告警、专用限流与发布审查尚未完成。
- AppGallery 正式上架与未成年人模式安装验证尚未完成；不得开发侧载或绕过路线。
- 因此 Harmony、建档、设备、积分申报、数据权利新建和 legacy 儿童入口等生产功能门必须继续默认关闭；删除、终止和撤回安全入口的保留不等于允许上线儿童生产功能。
