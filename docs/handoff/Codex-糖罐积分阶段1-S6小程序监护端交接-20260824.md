## 已完成

1. 建立小程序监护端 v2 基座：固定 HTTPS 源、严格相对 `/api/v2/...` 路径、公开/成人鉴权分离、稳定错误结果、写请求不自动重试、密码学安全幂等键、当前会话快照和旧响应丢弃。新增页面只能通过端点白名单 `guardianApi` 调用服务端，不自行拼接认证头。
2. 成人会话只持久化白名单用户字段。A→B 会话替换先写入并读回验证空 Token 墓碑，再暂存 userB，最后写 tokenB 并整体复核；任何中间失败都不会留下 `userB + tokenA`。清理失败会阻断本机会话使用，而不是退回内存或旧磁盘状态。
3. 服务端新增 `GET /api/v2/children`，只返回当前成人本人具有历史 verified、可见范围监护证据的儿童最小模型；active、withdrawn、superseded 的严格最新版本均可用于安全入口发现，未授权同家庭儿童、其他监护人和跨家庭数据不回显。
4. 服务端新增 `GET /api/v2/guardian-consent-operations/:operation`，按家庭、成人、操作和 `Idempotency-Key` 精确查询 enrollment/reconsent 是否完成，不返回资源 ID 或儿童正文，并且不受创建功能门关闭影响。
5. 授权向导在儿童数据提交前只读取公开法律文本。四类文本与监护关系声明分别确认，提交时冻结版本/SHA-256/关系/别名证据并执行动作专用 reauth。授权页在隐藏或账号切换后清理密码、断言与勾选状态，回前台重新读取法律证据。
6. 授权建档和重新授权在网络写入前创建经读回验证的 durable 非秘密恢复标记。标记只包含操作和幂等键，不包含儿童别名、密码、reauth 或法律正文；存储不可验证时请求不会发出。应用重启后先以原键对账，`not_found` 不依据客户端时钟自动放弃，恢复槽位满时也不会静默淘汰未决操作。
7. 设备管理覆盖创建/恢复配对、短码和 challenge 的仅内存展示、claimed 设备识别、家长二次确认、设备撤销和会话撤销。监护端 API 不暴露孩子 claim、签名完成或 Refresh 能力。配对创建同键重放可在服务门关闭后恢复 pending/claimed 状态；过期会按服务端时间推进，终态不返回短码或 challenge。
8. 撤销 pending binding 由 007 数据库触发器原子取消 pairing、proof challenge 和设备会话；服务端 confirm 再次要求 claimed binding 仍为 pending。同键创建重放会返回 cancelled 且不泄露秘密，旧 challenge 不能完成确认。
9. 家庭待办覆盖待办汇总、状态筛选、不透明游标分页、详情、退回补充、批准、调分和驳回。动作携带当前服务端 revision；双击只发出一次写入，畸形 2xx 保留原 action/key，不宣称成功。
10. 家庭与隐私覆盖本人历史授权、撤回、数据权利列表/详情、查阅、导出、更正别名、删除和终止服务。撤回在 active、processing_blocked 和 deletion_pending 路径均按服务端状态机校验，且不会把 deletion_pending 降级。
11. 数据快照对顶层、各数组元素、嵌套规则/法律证据、时间、状态、revision 与请求/儿童 ID 做严格校验，再按字段白名单生成安全视图。完整白名单快照只在当前页面内存分区展示；不写文件、不写剪贴板、不写本地缓存，也不保留密码、Token、Refresh、密钥、公钥或未知字段。
12. 授权、数据行权、积分审批、设备/会话 mutation 的成功响应均绑定原操作、目标资源、目标状态和 revision。网络失败、超时、畸形网关或畸形 2xx 按结果未知处理，在页面仍可见时保留原内存意图、reauth 和同一幂等键，禁止以新键误报成功。
13. 新页面已注册到小程序，正式版保持新增儿童、设备和待办等封闭入口不可发现；公开法律文本及家庭隐私安全入口常驻。旧请求 body 中的重复 Token 已移除，历史请求也加入会话代次保护。

## 已知低优先级工程项

- 开发版/体验版仍使用代码中的固定生产 API 域名。建立编译时受控、不可由客户端改写的独立合成非生产端点，并让预览模式拒绝生产 host 之前，不得执行联网全链 smoke。
- 普通数据行权的结果未知意图当前只存在页面内存，用户可主动放弃，页面隐藏也会为清理 reauth 而丢弃该意图；生产前需要非秘密 durable 恢复句柄和服务端状态对账，避免随后以新键生成重复请求/审计记录。
- 法律文本 `web-view` 当前只验证 HTTPS，尚未限定正式法律域名和路径，也未补齐 `binderror` 页面反馈。
- 配对页人工核对只展示缩短指纹；应改为更长、分组、易比对的形式，但服务端 proof 始终使用完整公钥和 SHA-256，不受展示长度影响。
- 当前页面内存会一次性物化完整导出。生产闭环需要专用限流、容量上限、流式或异步生成、安全文件交付和每次实际披露回执，不能静默截断，也不能把系统剪贴板当成安全交付渠道。
- 尚未在微信开发者工具执行 WXML/WXSS 编译、合法域名校验和受控成人账号真机 smoke；Node 测试和静态门不能替代这些验收。
