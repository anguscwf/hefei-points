# ADR-0003：阶段 1 采用安全前置的纵向切片

- 状态：已接受
- 日期：2026-08-23
- 决策人：安总

## 背景

阶段 0 已证明 HarmonyOS 工程、签名和 AppGallery 上传链路可用，但华为工单明确确认实名未成年人账号不支持 AppTest，且未成年人模式暂无其他官方测试应用分发能力。项目已经决定改走完成合规和产品闭环后的正式上架路线。

本轮源码审计发现，现有家庭与积分底座可复用，但匿名配置、儿童创建、儿童积分/历史查询和旧 Token 均存在与儿童端隔离及授权要求冲突的边界。若直接开发 HarmonyOS 页面或只在新 v2 API 上叠加功能，旧接口仍可能绕过新门禁。

## 决定

- 阶段 1 先完成 S0 安全前置，再按“授权建档 → 设备配对与会话 → 孩子本人只读 → 积分申报审批 → 数据行权 → 小程序监护端”实施。
- HarmonyOS 儿童端不复用旧儿童密码 Token、全家庭积分接口或全家庭历史接口，只使用设备绑定的 v2 本人接口。
- 新儿童只能在重新认证、监护关系声明和三份独立文本同意同一事务中创建；家庭管理员角色本身不构成监护授权。
- 所有儿童生产功能使用默认关闭的服务端开关；合成数据验证通过不等于允许处理真实儿童数据。
- 数据库迁移按授权、设备、申报、数据行权四批增量执行。回滚保留授权、申请和审计数据，以关闭功能门和回退代码为主。
- 旧 API 的安全问题必须修复并增加回归测试，不能只依赖新客户端“不调用”。

详细清单见 [阶段 1 现有能力审计与首批实施清单](../plans/阶段1-现有能力审计与首批实施清单-20260823.md)。

## 影响

- 阶段 1 的首个代码提交是安全修复，不是 HarmonyOS UI 或设备配对功能。
- 小程序需要把微信登录提示、监护授权、设备确认、家庭待办和数据权利拆成不同业务流程。
- 旧家长端接口保持兼容，但旧儿童新增和旧儿童读取能力必须被服务端收窄或关闭。
- 首发周期会增加迁移、威胁测试和合规门禁工作，但可以避免在正式上架前形成无法修补的授权和账本分叉。

## 后续动作

1. 完成 S0 匿名枚举、跨孩子读取、旧儿童新增和 v2 鉴权回归；
2. 实施 006 授权建档迁移和原子 API；
3. 建立迁移前备份、完整性与前滚/代码回退演练；
4. 按切片推进设备、申报审批、数据行权和小程序监护端；
5. 在任何真实儿童数据处理前完成总体方案规定的存量整改、PIPIA、保留表和公开文本硬门。
