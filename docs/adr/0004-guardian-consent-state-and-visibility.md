# ADR-0004：监护授权、儿童状态与可见性边界

- 状态：已接受
- 日期：2026-08-23
- 决策人：安总

## 背景

阶段 1 的 006 迁移需要同时解决三个问题：家庭成人角色不能自动等同于监护授权；存量儿童不能在没有有效证据时继续处理；撤回、多监护人和幂等重放不能产生相互矛盾的状态。

真实隐私政策、儿童个人信息保护规则、儿童用户协议、敏感个人信息单独告知以及监护关系声明尚未完成正式法务定稿，因此代码不能伪造或预置生产版本。

## 决定

- `admin`/`parent` 只表示家庭角色。成人只有持有本人对特定儿童的 `active guardian_consent`，且儿童 `child_privacy_states.status` 为 `active`，才能经旧家长端读取或修改该儿童数据。
- 006 不写入任何伪造法律文本。四类法律文本由受控发布流程写入 `legal_text_versions`；监护关系声明通过版本、SHA-256 和 HTTPS 公开地址配置。缺失任一正式证据时建档失败。
- 授权核心证据不可变，只允许受控地从 `active` 推进到 `superseded` 或 `withdrawn`。重新同意生成新版本，不修改旧版本。
- 新建儿童、零余额账户、授权证据、隐私状态和幂等记录在同一事务完成；孩子不创建可用密码凭据。
- 存量儿童回填为 `suspended_pending_consent`，不自动激活。共享账本只依据隐私状态决定是否允许新增处理；`HARMONY_CHILD_ENABLED` 仅控制 HarmonyOS/v2 新流程，不能误伤旧家长端。
- 任一监护人的最新授权为 `withdrawn` 时，儿童进入全局 `processing_blocked`。其他监护人可以补充新授权证据，但不能覆盖该撤回；只有所有撤回方以新版本重新同意后才恢复 `active`。
- 幂等键只保存摘要、请求指纹和资源/状态 revision，不保存原始凭据或完整响应。记录长期保留以阻止重复建档；资源状态已变化时，旧键返回 `IDEMPOTENCY_REPLAY_STALE`，不得拼接旧授权和新状态。
- v2 重新认证断言只接受 Bearer 会话、有效期 5 分钟、一次消费，并绑定用户、家庭和用途。

## 影响

- 旧家长端在没有本人有效授权时不会显示儿童，也不能通过积分、历史或配置接口绕过授权。
- 撤回后旧儿童 Token 和成人旧接口都受隐私状态限制；后续 007 还必须在撤回事务中撤销设备会话。
- 多监护人争议采用保守停止处理规则，不自动推定某一成人可以替另一成人恢复处理。
- 正式法律文本、PIPIA、保留期限和存量数据整改仍是生产开放硬门；合成测试通过不构成上线授权。

## 后续动作

1. 在 007 中让设备绑定和会话引用有效授权版本，并在撤回时同步撤销；
2. 在 009 中加入数据行权、保留决定和字段白名单审计；
3. 小程序实现独立授权向导，不把家庭管理员登录提示包装成监护同意；
4. 正式开放前由合规流程发布四类法律文本和监护关系声明。
