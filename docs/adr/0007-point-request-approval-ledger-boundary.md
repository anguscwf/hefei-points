# ADR-0007：积分申报、审批与来源流水边界

- 状态：已接受
- 日期：2026-08-23

## 背景

孩子端不能直接修改积分账本。积分申报同时面对设备重试、同一任务重复提交、规则改名或删除、双监护人并发审批、授权撤回、跨家庭猜测以及旧历史接口软删除流水等风险。现有 `points.changePoints()` 会自行开启事务并在账户缺失时补建账户，也不能直接用于审批原子事务。

## 决定

1. 积分申报只通过 `/api/v2` 提供，并由 `HARMONY_CHILD_ENABLED` 与 `POINT_REQUESTS_ENABLED` 控制；设备提交还必须通过既有 `DEVICE_PAIRING_ENABLED` 和设备 Access 会话门。任何新门都不会开启旧儿童登录或管理入口。
2. 设备请求中的家庭、儿童、绑定和会话全部从 Access 上下文推导。最终业务事务再次复验精确 active session、binding、儿童角色、隐私 active、创建绑定监护人的当前 active 授权，以及 `pointsLedger`、`pointRequests` 和 `childDevice=self_only` 范围。
3. 每个申请保存服务端解析的 reward 规则快照，包括稳定规则/分类 ID、名称、规则 revision、单位和 min/default/max。审批只使用提交快照，不重新解释后来改名、缩小范围或删除的规则。
4. `(device_binding_id, client_request_id)` 是设备领域重试身份；申请另保存 canonical 请求指纹。同一绑定同一 ID 的相同载荷返回原申请，不同载荷稳定冲突。不同绑定可以使用相同客户端 ID；孩子的共享设备视图只向来源绑定回显该 ID。家庭、儿童、规则和由服务端校验/归一化的实际发生时间派生出的上海日期周期只用于标记疑似重复，不静默丢弃第二条申请。普通补报期限仍待产品确认，因此当前先收紧为上海当日，缺省使用服务端提交时点。
5. 状态机为 `pending → needs_info/approved/rejected/cancelled` 和 `needs_info → pending/rejected/cancelled`。孩子同一儿童的任一当前有效设备可以补充或取消，避免换机后遗留申请卡死；只有 `pending` 可以批准。所有写操作要求 `expectedRevision` 和持久幂等键，成功事件只保存幂等键 SHA-256 摘要及不可变状态证据。
6. 成人身份本身不等于监护权限。列表、详情和审批只包含本人对目标儿童持有当前 active 授权，且授权范围包含 `pointsLedger=true`、`pointRequests=true`、`guardian=full` 的申请。越权和不存在统一隐藏资源存在性。
7. 批准申请、条件推进 revision、精确更新既有积分账户、插入来源流水和完成幂等事件共用一个 `BEGIN IMMEDIATE` 事务。缺失账户返回 `CHILD_DATA_INCOMPLETE`，不得补建。双监护人使用同一 revision 时只能有一个事务成功。
8. `transactions.source_type/source_id` 对积分申报来源成对出现；同一家庭同一来源全历史唯一。数据库校验来源流水与已批准申请的家庭、儿童、分值、规则快照、操作人及 transaction ID 一致。带来源流水禁止修改、软删除和硬删除；更正必须由未来显式反向流水完成。
9. 任一监护授权撤回继续以 ADR-0004 的儿童全局阻断为准，并由 007 撤销设备会话。未决申请作为审计证据保留，但隐私状态不再 active 时所有设备操作和成人审批均被阻断，不产生积分流水。

## 影响

- 孩子可以安全申报并查看本人状态，但没有直接记分能力。
- 网络重试、服务重启和双亲竞争不会制造重复申请、重复余额或重复来源流水。
- 规则配置变化不改写已提交申请或已批准流水的含义。
- 旧历史删除/备注接口遇到审批来源流水会安全失败，普通无来源旧流水保持兼容。
- 008 为前向迁移；应用回退时保留申请、事件和来源证据，生产回退只能关闭功能门并使用兼容代码。

## 后续动作

- S5 的通用审计与数据行权必须把 point request、事件和来源流水纳入查阅、导出、更正、撤回及删除边界，不得删除法定或账本证据。
- 家长小程序待办中心采用当前单条审批 API；批量审批、照片、Push 和用机兑换继续留在后续阶段。
- 正式发布前完成法律文本、PIPIA、存量数据整改、留存/删除策略、密钥轮换、备份恢复、容量监控和 AppGallery 审查。
