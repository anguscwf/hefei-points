# ADR-0001：以 hefei-points 独立仓库作为唯一真源

- 状态：已接受
- 日期：2026-08-20
- 决策人：安总

## 背景

现场同时存在三层 Git 状态：

1. `Documents\糖罐积分` 是无提交、无远程的资料空壳仓库，混有发布包、截图、工具缓存和历史资料；
2. `C:\Users\ANGUS\projects` 是父仓，历史曾将 `hefei-points` 当普通目录跟踪；
3. `C:\Users\ANGUS\projects\hefei-points` 是拥有糖罐专属历史的独立仓库，基线整理前为 `main@f48cc69`。

父仓和子仓曾同时指向 `git@github.com:anguscwf/projects.git`，但提交历史彼此独立；远端还存在 `main` 与 `master` 双分支。直接合并、重置或推送可能覆盖正确历史，也可能重新暴露父仓历史中的运行数据。

## 决定

- 以独立的 `hefei-points` 仓库作为糖罐积分唯一 canonical 仓库。
- 保留其现有提交历史，并在 `codex/repo-baseline-20260820` 上建立分主题基线。
- 本轮不修改父仓、不修改远程、不推送，也不重写任何历史。
- `Documents\糖罐积分` 继续作为外部资料/发布证据目录；仅将清理后的核心 Markdown 文档复制进本仓库。

## 影响

- 后续所有源码、核心产品方案和 ADR 都应在本仓维护。
- 父仓仍可能显示同一工作树的变化；在完成后续解耦前，不得从父仓暂存或提交 `hefei-points/**`。
- 当前远程不能被视为已整理完成的项目远程；本地 ahead/behind 只用于观察，不构成推送授权。

## 待后续单独处理

1. 为糖罐建立独立远程并核对默认分支；
2. 在不删除工作目录的前提下，让父仓停止跟踪 `hefei-points/`；
3. 审计父仓历史中的 `data/`、`data-dev/`、`backups/`、SQLite 和私有配置；
4. 根据远端实际对象决定是否需要历史清理、凭据轮换与协作者通知；
5. 评估并关闭或归档远端 `main`/`master` 双分支问题。
