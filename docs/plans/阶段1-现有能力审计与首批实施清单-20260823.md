## 1. 结论

现有 Express、SQLite 和微信小程序可以作为阶段 1 的工程底座，不需要重写。家庭隔离、积分账户与流水、稳定规则 ID、规则版本、事务封装、`revision` 条件写、临时数据库测试和小程序统一请求封装都可以复用。

但是，现有儿童账号、旧 Token、积分与历史查询、儿童创建和数据清理接口不能直接供 HarmonyOS 儿童端使用。它们目前不满足监护人授权、孩子本人最小可见、设备绑定、会话轮换、审批幂等和可审计数据行权等要求。

阶段 1 必须先完成安全前置，再依次实现“授权建档 → 设备配对 → 本人查询 → 积分申报审批 → 数据行权”。全部儿童生产功能默认关闭，只允许用合成家庭验证；本文件不代表已经对真实儿童数据完成盘点、取得授权或开放生产。

## 4. 必须先处理的 P0 问题

### P0-1：未登录可枚举全部家庭成员

`GET /api/config` 在没有 Token 时调用 `users.listAll()`，可能返回所有家庭成员的 ID、姓名、角色和家庭 ID。阶段 1 的第一项代码改动必须移除匿名成员列表；小程序未登录首页不得再依赖该响应展示用户。

验收：匿名调用不返回任何用户、孩子或家庭关联；旧家长登录方式仍可用；有安全回归测试。

### P0-2：现有儿童创建绕过监护人授权

`POST /api/family/child/create` 可直接创建孩子，且缺省密码为 `123456`；`/api/config/users` 也可以批量改写儿童。家庭管理员身份不等于已经验证的法定监护关系。

验收：旧儿童新增能力受默认关闭的服务端开关约束；新孩子只能通过原子的 `POST /api/v2/child-enrollments` 创建。事务必须同时验证短期重新认证、关系声明、三份公开文本和敏感信息单独告知同意，任一失败均不得产生孩子或授权记录。禁止固定默认密码。

### P0-3：儿童旧 Token 可读取兄弟姐妹数据

`GET /api/points` 会返回全家庭积分账户，`GET /api/history` 在未提供或提供无效 `kid` 时可能退化为全家庭流水。

验收：旧接口对 `child` 角色收窄并有回归测试；HarmonyOS 只使用 `/api/v2/me/summary`、`/api/v2/me/transactions`、`/api/v2/me/reward-rules` 和 `/api/v2/me/point-requests` 等固定设备接口。`childId` 必须从设备会话推导，客户端不能指定其他孩子。

实施状态：已完成 S3 本人只读切片。两个 `/api/v2/me` 接口严格只接受设备 Access Bearer；家庭、儿童、绑定和会话均来自认证上下文，业务查询再次复验 active session、binding、同一监护人的当前 active 授权、隐私状态、儿童角色以及 `pointsLedger/self_only` 范围。绑定仍保留创建时授权版本作为签发审计证据；正常续签后既有设备继续可用，当前授权撤回后立即失效。摘要不接受查询参数；流水只接受有上限的 `limit` 和作用域绑定的 AEAD 不透明游标，软删除、兄弟姐妹、跨家庭及内部字段不会进入响应。

### P0-4：当前备份发生在迁移之后

数据库连接会自动执行迁移，而现有备份脚本通过同一连接打开数据库，所以不能满足“旧库备份 → 校验 → 迁移”。旧 JSON 迁移脚本还在使用已经过时的规则表写法。

验收：提供不加载应用连接模块的迁移前备份流程，先复制数据库及 WAL、生成 SHA-256、执行 `PRAGMA integrity_check`，再启动兼容代码执行迁移；旧 JSON 迁移脚本修复并以临时库测试，或明确归档为不可用。

实施状态：已完成。`scripts/pre-migration-backup.js` 不加载应用连接，使用 SQLite `VACUUM INTO` 生成包含已提交 WAL 内容的一致性快照，并生成文件 SHA-256、全库逻辑内容 SHA-256、完整性、外键、迁移集合与业务计数清单。生产连接在有存量数据和待迁移版本时必须校验 `PRE_MIGRATION_BACKUP_MANIFEST`，并重算当前源库逻辑摘要；缺失、陈旧或不匹配时拒绝迁移。旧 JSON 迁移脚本的单独归档/重写仍留作后续历史清理，不用于 006 发布。

### P0-5：旧会话不能作为儿童设备会话

当前 Token 最长 30 天，自定义 HMAC 签名只截取 16 个十六进制字符，支持从 query/body 读取，没有设备绑定、短期 Access Token、Refresh 轮换、重用检测或持久会话。`/wx-bind` 还信任客户端提交的 `openid`。

验收：v2 只接受 `Authorization`；设备 Token 固定绑定 `familyId + childId + deviceBindingId`；Access 短期、Refresh 摘要落库并单次轮换；旧 Refresh 重用撤销整组；撤销设备或授权后立即失效；`openid` 只能由服务端换码得到。

实施状态：已完成。设备 claim、Access 和 Refresh 严格只接受 Bearer；Access 为 15 分钟，Refresh 为 30 天且只在 Access 剩余 5 分钟内签发单个 pending proof challenge。Refresh 按 token family 单次轮换，旧凭据非精确重试或超过固定幂等宽限后会撤销整组。设备、会话、授权撤回和儿童处理阻断均在持久状态上即时生效。

## 5. 不得误复用的旧能力

- 微信登录页的“同意授权”只是平台登录提示，不是监护人同意证据，必须改成准确文案。
- 家庭 6 位邀请码有效期和重用模型不同，不能复用为设备配对码。
- 家长直接调用 `/api/points/change` 的随手记能力不能作为儿童申报审批。
- `/api/history/delete` 仅隐藏流水且不冲正余额，不能删除审批流水；更正必须新增反向流水。
- 管理员“删除用户”和“清理历史”不能作为儿童查阅、删除或终止服务流程。
- 家庭 `admin/parent` 角色不能直接等同于已声明并验证的监护人。
- 现有内存限流重启后丢失，只能作为外围保护；短码失败计数和锁定必须持久化。

## 6. 迁移顺序

实际编号以当前 `005` 后续为准，每批独立迁移、独立测试，生产回滚采用“关闭功能开关 + 回退代码 + 保留新表数据”，不得直接删除授权、申请或审计数据。

### 006：授权与儿童建档

建议文件：`006_guardian_consent_enrollment.sql`

- `legal_text_versions`：四类服务端认可文本的版本、SHA-256、公开 URL 和生效时间；
- `reauth_assertions`：绑定用户、家庭和用途的 5 分钟一次性断言，只保存随机令牌摘要；
- `child_privacy_states`：`suspended_pending_consent`、`active`、`processing_blocked`、`deletion_pending`、`deidentified`、`deleted`；未授权孩子别名只允许保存在家长端本地草稿中，服务端不建草稿；

- 存量儿童默认进入 `suspended_pending_consent`，在完成独立合规盘点前不得自动激活。

实施状态：已完成。短码和持久失败主体使用分域 HMAC，claim、Access、Refresh 和 proof challenge 只落摘要；家长须使用独立高熵 challenge 和 `expectedRevision` 二次确认。设备使用 canonical P-256 SPKI 对分域 signing payload 签名，只有 proof 成功后设备身份才取得 active 唯一性，避免公开身份在 proof 前被抢注。授权撤回、设备撤销、会话撤销、配对/证明过期或锁定均通过事务和数据库触发器撤销相关安全产物。

### S17：本地单调授权账本与单次消费记录边界

本切片新增 `npm run init:synthetic-authorization-ledger` 与 `npm run consume:synthetic-deployment-grant`。两条 CLI 除 `--help` 外不接受参数，只从非 TTY stdin 接受最多 768 KiB 的单行 canonical JSON；初始化和消费分别要求 `SYNTHETIC_AUTHORIZATION_LEDGER_INIT_ACK=initialize-local-ledger-not-authority-v1` 与 `SYNTHETIC_AUTHORIZATION_CONSUME_ACK=record-local-single-use-not-deployment-v1`。初始化输入只含 schema 1、固定 purpose、唯一 request ID 和签名 revocation checkpoint；消费输入只含 schema 1、固定 purpose、唯一 request ID 和完整 S16 verification document。生产 API 不接受 test-only ledger 或 verifier 结果，测试 provenance 也不能被复制成生产回执。

账本固定名为 `synthetic-authorization-ledger.sqlite`，最大 16 MiB，必须位于 canonical 仓库、synthetic 数据根和信任策略目录之外的独立批准父目录，并与仓库位于同一本地卷。ledger ID、consumer、目标环境、策略、文件 identity/inode 与主机/OS 账号上下文在 genesis 中固定；跨路径、跨文件或跨主机复制会 fail closed。SQLite 固定 `journal_mode=DELETE`、`synchronous=FULL` 和 `BEGIN IMMEDIATE`；WAL/SHM 始终拒绝。正常并发产生的瞬态 DELETE journal 与崩溃遗留 hot journal 必须让 SQLite 在可写排他入口中恢复，不能在加锁前把合法同行事务误判为攻击。

初始化对同一签名 checkpoint 前后验证两次再记录 genesis；精确原请求可重放，不同请求不得接管既有账本。消费先在事务内完整校验 schema、不可变 trigger、全部 checkpoint/回执/拒绝/block 摘要和账本上下文，再对新请求运行 S16 verifier 并要求 schema 2 结果。相同 sequence 必须具有相同 checkpoint 摘要，下一 sequence 必须精确 `+1`；key、principal、approval 与 grant 四类吊销集合只能累计。同序列分叉或删除既有吊销项会提交不可变 block 并永久封锁该账本；rollback/gap 不推进。有效的新 checkpoint 即使 bundle 随后被拒，也会与稳定 rejection 一起持久记录，避免调用方降级重试旧 checkpoint。

新消费在同一个 `BEGIN IMMEDIATE` 中复核 checkpoint、S16 束和本机观察时间，绑定 policy/consumer/target、grant、grant envelope、approval envelope 以及 target/source/implementation/configuration 元组，并只允许一个本地记录。相同 request 和完全相同指纹可在 verifier 前恢复历史 receipt 或稳定 rejection；同 request 不同指纹冲突，同 grant、approval 或候选目标的新 request 稳定拒绝。提交结果无法证明时只返回 `SYNTHETIC_AUTHORIZATION_LEDGER_RESULT_UNKNOWN`，必须用精确原请求恢复，不能换键试探。本地时钟不得倒退且提交时必须仍未过期，但本机时间没有外部可信证明。

S17 只写独立 ledger，不写 synthetic 业务 SQLite，不联网、不调用真实部署器，也不把部署动作和回执纳入同一事务。`local_single_use_record_committed` 只表示本 ledger 实例已提交本地单次使用记录；它不证明 checkpoint 是权威最新、不提供跨 ledger/主机/consumer 的全局防重放、不认证 consumer 或外部角色，也不等于 grant 已全局消费。初始化成功、首次消费成功与历史 receipt replay 全部继续输出 `deploymentAuthorization=not_granted`、`productionChildGateState=not_observed`、`childUseAuthorization=not_granted`；历史 rejection replay 仍只恢复原稳定失败。完整契约见 `docs/runbooks/受控-synthetic-本地授权账本初始化与单次消费记录.md`。

### S19a-test-model：非规范性外部 saga 负向安全参考机

本切片只在 `server/test-support` 新增纯同步、确定性的 `inspectSyntheticExternalSagaReferenceTraceForTest`，并以 ADR-0009 固定 test-only 边界。它只接受与 S19-readiness test seam 固定输出一致、`testOnlyOverridesUsed=true` 的完整 blocked report shape；只绑定 caller 对象的 shape/摘要，不认证其真实来源。production report、caller endpoint/credential/trust root/receipt、raw S18 document、未知字段、accessor、非普通对象和超限 trace 都稳定拒绝。模型不 import S17～S19 production API，不读取环境、当前时间、文件、SQLite、网络或生产数据，也不创建 CLI、package script、migration 011 或可持久化 receipt。因此 committed synthetic production provenance 仍精确为 43 个实现文件/十项迁移。

摘要化 model operation 绑定当前 blocked report、target/configuration、artifact、secret version、expected state、operation ID 与正整数 fence；coordinator、deployer、target、platform event source、state observer、health observer 和 no-effect proof issuer 的 actor/fault-domain 必须两两分离。reservation 与 outbox 只能作为同一条 `test_only_reservation_outbox_atomic_commit` reference event 出现；accepted、queued、HTTP 2xx、outbox dispatched、delivery ACK 与 signed ACK 只计数、不推进。target admission、平台事件、独立 read-after-write 和 health 必须按同 operation/fingerprint/fence 分开观察，缺一都不能形成完整 test-only forward shape。

dispatch UNKNOWN 在单条完整 trace 内保持 sticky；只有同一 operation/fingerprint/fence 的完整正向观察链，或在未见 admission/platform/read 时带变更前状态、target fence high-water、低 fence 拒绝声明与 `not_applied` 状态的 modeled no-effect shape，才能在参考模型内形成完整 shape。矛盾 read 进入独立 unresolved 状态，不能再由 no-effect 洗掉。即使如此，输出仍固定 `authoritativeNoEffectProofVerified=false`、`realExternalUnknownReconciledByThisModel=false`。unhealthy 只进入 `test_only_compensation_protocol_required`；v1 不接受 compensation/rollback/release/refund/grant-reuse 事件，不自动释放 reservation 或复用原 grant。纯函数没有跨调用状态或状态 token，不能证明跨 trace replay/fence 历史、全局幂等或防回滚。

只有完整安全 shape 最多返回 `result=no_modeled_safety_violation_detected`；不完整或阻断 trace 固定使用 `no_positive_conclusion` 结果。所有返回的 `referenceCoverage=minimum_selected_non_exhaustive`，并始终保持 `referenceModelNormative=false`、协议 conformance/readiness/外部事实/真实 reservation/outbox/admission/fence/观察/补偿/回滚验证为 false，部署状态未观察，部署和儿童授权未授予。该结果不是真实 S19 进展、部署许可、回执或发布证据，且不关闭 S19-readiness 17/14 阻断集合中的任何一项。

### S20a：设备积分申请详情与写操作历史结果对账基座

本切片与真实 S19 正交，只关闭 S8 留下的设备单条详情和写操作历史结果对账技术缺口。服务端新增 `GET /api/v2/me/point-requests/:id`；同孩子任一当前有效设备可读取当前最小详情，但来源 `clientRequestId` 只向来源绑定回显，跨家庭/儿童/无权设备统一隐藏。另新增 resubmit/cancel 两个 POST 对账入口；POST 只承载原请求体和原 `Idempotency-Key`，在只读事务中查历史事件，不执行 mutation、生成事件或写状态。

对账严格绑定来源设备、原 action、申请 ID、expected revision、NFC/trim 规范化载荷和原键摘要。`completed` 只在唯一历史事件及家庭/儿童/设备/actor/transition/revision/timestamp/当前记录单调演进全部一致时返回，并且只包含当时 `fromStatus`、`toStatus`、`resultRevision`、`recordedAt`；它不是当前申请状态，`currentResourceStateIncluded=false`，客户端随后必须读取单条详情。`not_observed` 只表示当前一致性快照没有观察到匹配事件，不是 no-effect 证明；固定保留原意图，只能原键原载荷重试。跨 action/申请/载荷的同键复用稳定 `IDEMPOTENCY_CONFLICT`，事件损坏、歧义或无法证明唯一完整结果稳定 `IDEMPOTENCY_RESULT_UNAVAILABLE`。

HarmonyOS 只增加设备详情与对账的 canonical request、严格 DTO/parser、exact allowlist 和只读 client 方法，拒绝错误 action/ID/revision/transition/observation、未知字段、`null` 和不安全整数。`mutating=false` 只表示对账请求本身只读；错误或 `not_observed` 不会让原写操作变成安全可丢弃。本轮没有 migration 011、PATCH/cancel mutation client、页面按钮、业务 coordinator、AssetStore mutation intent 生命周期、外部网络或部署。

`POINT_REQUESTS_ENABLED` 关闭时只保留历史对账恢复；设备详情和正常写操作仍门控。对账始终要求 `HARMONY_CHILD_ENABLED`、`DEVICE_PAIRING_ENABLED`、当前有效设备 session/binding/token family/rotation、active 隐私与监护授权、账户和家庭/儿童/设备作用域；撤权仍阻断处理并撤销相关设备会话。未决 description 的生产保留期限和监护人授权安全放弃策略未获批前，不得开放补充、取消或重新提交 UI。

### S20b：HarmonyOS 设备积分申请单条只读详情界面

本切片只把 S20a 已有 `getPointRequest` client 接入 `ChildSessionCoordinator` 与现有 `Index` 单页。协调器只接受当前已经加载的申请列表中恰好一条匹配、格式 canonical 的申请 ID；重复 ID、未加载 ID 或畸形 ID 在发网前稳定拒绝。读取只能由用户点击“查看最新详情”触发，不自动轮询；selected detail 只保存在内存，用户可以“收起详情”，不新增页面路由、Preferences、AssetStore 槽位、文件或剪贴板处理。

返回详情必须保持申请 ID、规则快照、申报分值、发生/提交时间、重复标记和来源设备可见的 `clientRequestId` 身份不变，revision 不得回退；同 revision 时状态、批准分值、说明、家长补充请求、处理决定或更新时间任一漂移都按 `PROTOCOL_ERROR` fail closed。更高 revision 只在 `updatedAt` 表示的真实时间点严格前进且旧状态非终态时原位替换当前列表项并成为 selected detail，不插入第二条申请，也不把列表或历史回执推断为当前状态。Access 过期最多沿用既有 proof/Refresh 机制轮换一次，再以精确原 ID 重试；收起、后台 generation 变化、儿童处理阻断，或下一次请求收到明确撤权/授权错误时会清除详情；本地 generation 已推进后，迟到响应不能重新显示。客户端没有主动撤权推送，远端已完成读取后发生的撤权由后续请求或生命周期切换触发本地清理。

`Index` 只展示当前状态、规则快照、说明、积分、家长留言/处理说明和时间，不显示 `clientRequestId` 或内部申请 ID；详情 Builder 直接绑定 selected snapshot，避免稳定列表 key 保留旧行对象。静态词法门扫描 HarmonyOS 消费层源码（仅排除 `ApiClient.ets` 与 `ApiContracts.ets` 协议/client 基座），并要求 `Index` 与 `ChildSessionCoordinator` 必须存在于检查集合，拒绝 `reconcilePointRequestOperation`、`PointRequestOperation` DTO、resubmit/cancel、PATCH 或两个 operation reconcile 路径的直接符号与字面路径。该门是 defense-in-depth，未来 wrapper、别名或计算属性仍须人工复核 import/call graph。本轮没有 server、migration、write、reconcile 调用、persistent mutation intent/coordinator、外部网络、部署或新 production state；S20a 对账基座仍不被 UI 调用。description 保留期限和 guardian-authorized safe abandonment 未获批准前，补充、取消和重新提交 mutation 继续阻断。真实 S19 仍未开始。

### S20c：HarmonyOS 设备积分申请列表单调分页边界

本切片不增加服务端能力，只加固 `ChildSessionCoordinator` 对既有本人申请列表 GET 的完整刷新和继续分页。每个响应页必须按服务端契约的 `(submittedAt, id) DESC` 严格降序；申请 ID 必须 canonical，并在本页与已接受历史页之间保持唯一；来源设备可见的 `clientRequestId` 也只能映射到同一申请，完整刷新不得把既有可见键改绑到新 ID。对完整刷新中仍可见的每个旧项逐项执行 S20b 同等级的 revision、状态、规则/申请身份和真实时间单调检查；缺席只表示当前页不可见，不推断为终态或删除。

继续分页必须使用精确当前游标。空页不得携带下一游标，下一游标不得等于当前游标，也不得与已接受游标历史形成 A→B→A 等循环；重复、乱序、跨页 ID/可见键冲突或非前进快照都在应用前以 `PROTOCOL_ERROR` fail closed。列表协议污染后保留此前已验证的只读申请列表与 selected detail 供用户查看；详情协议错误会清除 selected detail。两类错误都会清空 reward rules、规则/申请游标及其历史，阻断继续分页和沿用旧规则创建申请。存在未决申请创建 intent 时，协调器与 UI 都禁用“加载更多”。generation 变化后的普通迟到成功或普通错误不改变新状态，但确定性的 `SESSION_REVOKED` / `CONSENT_REQUIRED` 仍执行既有撤权安全清理；Access 过期仍最多轮换一次后以精确游标重试。

S20c 新增/变更的列表、详情与分页范围保持只读，既有 S8 创建路径不变：没有 operation reconcile 调用、resubmit/cancel/PATCH、mutation UI、持久 mutation intent/coordinator、server、migration、新路由或新存储。既有 Access/Refresh 轮换和确定性撤权时清理本地会话/旧意图是授权安全后果，不是 S20c 申请 mutation。本轮也未决定 description 保留期限或 guardian-authorized safe abandonment；政策获批并形成新 ADR 前不得据此开放补充、取消或重新提交。

## 9. 功能门与启用规则

默认值全部为 `false`：

- `harmony_child_enabled`
- `child_enrollment_enabled`
- `device_pairing_enabled`
- `point_requests_enabled`
- `child_data_rights_enabled`

当前服务端环境变量与逻辑门对应如下；只有 `1`、`true`、`yes`、`on`（不区分大小写）会开启，未设置或其他值均按关闭处理：

| 环境变量 | 用途 |
| --- | --- |
| `HARMONY_CHILD_ENABLED` | HarmonyOS/v2 儿童新流程总门；不控制共享旧家长端 |
| `CHILD_ENROLLMENT_ENABLED` | 监护授权与儿童建档 |
| `DEVICE_PAIRING_ENABLED` | 设备配对与设备会话 |
| `POINT_REQUESTS_ENABLED` | 积分申报审批 |
| `CHILD_DATA_RIGHTS_ENABLED` | 儿童数据行权流程 |
| `LEGACY_CHILD_LOGIN_ENABLED` | 仅用于显式兼容验证的旧儿童密码登录，生产保持关闭 |
| `LEGACY_CHILD_MANAGEMENT_ENABLED` | 仅用于显式兼容验证的旧儿童增删改，生产保持关闭 |

新流程开关不能连带开启任何 `LEGACY_*` 开关。

`CHILD_DATA_RIGHTS_ENABLED` 只门控新的 access/export/correct 请求；既有请求状态、回执和已授权导出保持可读，withdraw/delete/terminate 不受该门或 Harmony 总门封锁。删除/终止仍受动作专用重新认证、本人历史监护证据、revision、幂等和策略阻断作业约束，功能门关闭不等于放宽授权。

`POINT_REQUESTS_ENABLED` 关闭只允许来源设备恢复既有 resubmit/cancel 的历史结果对账；设备单条详情、申请创建和其他写操作仍关闭。该恢复例外不绕过 Harmony/设备门、有效设备会话、隐私、监护授权、账户或家庭/儿童/设备隔离，也不得借 POST 对账入口执行 mutation。

生产开启设备配对时必须同时明确客户端地址边界：直连部署使用 `PAIRING_CLIENT_IP_MODE=direct`；反向代理部署使用 `PAIRING_CLIENT_IP_MODE=trusted_proxy`，并在 `TRUSTED_PROXIES` 中配置实际可信代理 IP/CIDR。未声明时生产启动拒绝开启设备配对；边缘层仍需独立限流和容量保护。

法律文本服务必须显式配置不带路径、端口、用户信息、查询或片段的精确 HTTPS `LEGAL_PUBLIC_ORIGIN`，并让数据库公开 URL 和监护关系声明公开 URL 都匹配固定类型、版本和摘要叶子。配置缺失或任一证据不匹配时不发布当前法律文本，也不得开启授权建档。

用于设备凭据派生、本人流水及积分申报列表游标 AEAD 的服务端根密钥必须纳入生产密钥托管、轮换与单密钥签发量监测；上线前须明确轮换后旧凭据、旧游标的失效和客户端恢复策略。

共享旧家长端不读取 `HARMONY_CHILD_ENABLED`；它以 `child_privacy_states` 为全渠道合规真值门，并额外要求当前成人本人持有该儿童的 active 监护授权。这样关闭 HarmonyOS 新流程不会误伤已授权家长操作，而 suspended、processing_blocked 等状态仍会阻断所有客户端新增处理。

功能门是应急止损手段，不是绕过正式上架的私有分发方式。首次正式上架前，只有在总体计划的合规、迁移、隔离、删除、备份和发布硬门全部满足后，才可面向符合条件的普通家庭开启核心能力。
