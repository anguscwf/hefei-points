## 小程序 rulesData truthiness bug 修复（22:00-22:10）

**问题**：用户报告"选择用户里是空的"，控制台有 timeout 错误 + `rewardRules`/`punishRules` 期望 Array 但收到 non-array 警告。

**服务器验证**：curl 测试 `159.75.102.145:3001/api/config` 返回 200，数据完整（4用户 + 规则完整）。

**代码 bug 修复（P5-P7）**：
- **P5 · rulesData truthiness bug**：`g.rules || {reward:[],punish:[]}` 当 `g.rules` 为 `{}`（空对象，truthy）时不触发 fallback，导致 `rewardRules`/`punishRules` 传 `undefined` 到 action-sheet 组件触发 Array 类型警告。
  → 修复：改为 `(g.rules && Array.isArray(g.rules.reward)) ? g.rules : fallback`
  → 影响文件：`index.js:96`, `mine.js:41`

- **P6 · API 失败无反馈**：`refreshState()` 中 `/api/config` 失败时静默忽略，用户看到空选择器无任何提示。
  → 修复：添加 toast 错误提示 + `.catch()` 处理

- **P7 · onLaunch 不加载 rules**：`app.js:onLaunch` 只设 `allUsers` 不设 `rules`，导致 rules 在页面首次渲染时可能为 null。
  → 修复：同时保存 `res.rules`

**根因分析**："选择用户为空"的根本原因是小程序内 `wx.request` 到服务器超时。服务器本身可达（curl 200），但微信开发者工具的请求可能受网络代理/防火墙影响。建议检查开发者工具「不校验合法域名」设置（已确认 project.config.json 中 `urlCheck: false`）。

## P8 · 超时+竞态核心修复（22:13-22:25）

**问题**：虽然 P5-P7 修了 truthiness/错误提示/rules 保存，但用户反馈依旧没内容。截图显示 `Error: timeout`（3642ms）+ `TypeError: Cannot read property 'name' of undefined`。

**根因（2层）**：
1. `wx.request` 没设 `timeout`，网络波动导致超时时静默返回 `{success:false}`
2. `onLaunch` 异步请求 `/api/config` 和页面 `onLoad→refreshState` 同步渲染产生竞态 — 页面在数据回来前就渲染了

**修复（4个文件）**：

### app.js
- `fetchAPI`：加 `timeout: 15000`（默认15秒），错误信息 `errMsg` 写进 `message`
- 新增 `_initDataReady()`：创建 `dataReady` Promise，页面可 await
- `onLaunch` 改为 `_loadConfigWithRetry(3)`：
  - 最多3次重试，指数退避（1s / 2s / 4s）
  - 成功/失败都 resolve dataReady，页面据此判断

### index.js
- `refreshState`：检测 `allUsers` 为空时等待 `dataReady`（3秒兜底超时）
  - dataReady=true → `_doRefreshState()`
  - dataReady=false/timeout → `_fetchConfigFallback()` 主动拉取
- 新增 `_fetchConfigFallback()`：主动请求 `/api/config`，带超时 + toast 提示
- 新增 `_doRefreshState()`：抽离渲染逻辑，去重
- `loadHistory`：防御 `data` 为 null 的情况
- `onSelectUser`：防御越界取值

### mine.js
- `onShow`：同样等待 `dataReady`，失败时主动拉取

### 防御性修复
- `loadHistory`：`!data || !data.history` 防止 null TypeError
- `onSelectUser`：`!opts || !opts[idx]` 防止越界

- 新增 `forceRelogin(msg)`：清除 localStorage token + alert 弹窗提示"登录已过期，请重新登录"

## P10 · HTTP版操作响应慢优化（22:48-22:58）

**问题**：加减分操作后等半天才更新分数和积分记录

**根因**：每次操作后前端调了 4 个 API：
- POST `/api/points/change` (1.4s)
- GET `/api/points` (1.4s) — 冗余！change 响应已包含最新分数
- GET `/api/config` (1.4s) — 冗余！
- GET `/api/history` (1.4s) — 可通过 prepend 优化

总延迟 ~5.6 秒。

**前端优化（index.html，已改好）**：
- `doChange`：直接用 `res.points` 更新分数，跳过 `loadData()` → 省 2 次 API
- `updateUI(skipTabRefresh)`：增加参数跳过 tab 刷新
- 新增 `prependHistoryRecord(record)`：把新记录直接插入 DOM，不用请求服务器
- `submitVoice`：同样的优化

**效果**：4 次 API → 1 次 API，~5.6s → ~1.4s（4倍提速）

**服务器端优化（server-v4.0.js，已改好待部署）**：
- 新增 `cachedRead()` + `invalidateCache()` 内存缓存
- 热点路径用缓存：config(15-30s TTL)、points(3s TTL)、history(3s TTL)
- 写操作后自动清除对应缓存

**⚠️ 两个文件都需要部署到服务器**：
- `index.html` → `~/hefei-points/public/index.html`
- `server-v4.0.js` → `~/hefei-points/server.js` + 重启进程
